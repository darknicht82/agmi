# Semilla — Ofertas hipótesis (embudo inicial)

> **Archivo operativo interno.** Son HIPÓTESIS, no un catálogo cerrado. El mercado dirá cuál se sostiene.
> Se ponen a prueba en el ciclo de 4 semanas (ver `docs/09_plan_implementacion.md`).
> Nomenclatura: descriptores neutros. Nombres reales en `docs/_mapeo_interno.md`.

## Por qué existen

Cuando no hay clientes suficientes, la matriz no se llena con "clientes que ya tienes". Se llena con **hipótesis de mercado**: *¿qué problemas suficientemente costosos existen en mercados a los que puedo llegar?*

Estas cuatro son las apuestas iniciales derivadas de las capacidades reales (`data/seed/capacidades.md`) y de la señal de pago ya observada.

## A — Formación práctica en IA

| Campo | Valor |
| :--- | :--- |
| **Problema que resuelve** | Profesionales y equipos que saben que la IA existe pero no la aplican a su trabajo real |
| **Oferta mínima** | Taller: *"IA práctica para profesionales: cómo usar [HERRAMIENTAS-IA] para trabajar más rápido y automatizar tareas reales"* |
| **Público** | Profesionales, equipos de pymes, formadores |
| **Formato** | taller individual · taller 3–5 personas · capacitación empresarial · acompañamiento |
| **Capacidad que lo sostiene** | C-05 (formación), C-07 (IA aplicada) |
| **Velocidad de entrega** | 1–7 días de preparación |
| **Inversión** | $0 |
| **Repetibilidad** | Alta (se puede empaquetar) |
| **Riesgo** | Genérico → "curso de IA" suena a todo y a nada. Tiene que ser **práctico y aplicado a tareas reales** |

> No vender *"curso de inteligencia artificial"*. Vender resultado: trabajar más rápido con tareas concretas.

## B — Automatización para pequeñas empresas

| Campo | Valor |
| :--- | :--- |
| **Problema que resuelve** | Dejar de copiar información manualmente entre [MENSAJERÍA], [CORREO], hojas de cálculo y sistemas |
| **Oferta mínima** | *problema → diagnóstico → automatización → capacitación* |
| **Público** | Pymes con procesos manuales visibles |
| **Capacidad que lo sostiene** | C-03, C-02, C-01 |
| **Velocidad de entrega** | 3–14 días |
| **Inversión** | $0 |
| **Repetibilidad** | Alta — *la automatización que se repite es la que se convierte en producto* |
| **Riesgo** | Vender la herramienta en vez del resultado. El cliente no compra [HERRAMIENTA-WORKFLOW]; compra *"quiero dejar de copiar datos a mano"* |

> Señal a observar: si 5 negocios piden lo mismo → candidato a producto.

## C — Diagnóstico tecnológico

| Campo | Valor |
| :--- | :--- |
| **Problema que resuelve** | Negocios que no saben qué tienen, qué les falta ni qué les está costando dinero |
| **Oferta mínima** | Revisión de computadores, red, backups, seguridad básica, correo, herramientas, procesos, automatización, presencia digital, oportunidades de IA → informe: *problema → riesgo → recomendación → prioridad → costo estimado* |
| **Público** | Pequeños negocios locales |
| **Capacidad que lo sostiene** | C-06, C-08 |
| **Velocidad de entrega** | 1–5 días |
| **Inversión** | Prácticamente $0 |
| **Repetibilidad** | Media-alta (se puede estandarizar) |
| **Señal de mercado** | **Ya existe**: una asesoría informática cobrada a un cliente comercial. Alguien entregó dinero a cambio de este conocimiento. Eso vale más que 100 reacciones en redes. |
| **Riesgo** | Convertirlo en consultoría interminable. Tiene que ser **informe breve y accionable** |

> **Es la hipótesis con señal de pago más fuerte de las cuatro.** Probable candidata al primer experimento.

## D — Desarrollo puntual de soluciones

| Campo | Valor |
| :--- | :--- |
| **Problema que resuelve** | *"Tengo un problema específico y necesito resolverlo"* — no "hazme una página web" |
| **Oferta mínima** | Integración · automatización · formulario avanzado · sistema interno · dashboard · tienda online · API · proceso de datos · herramienta interna |
| **Público** | Negocios con un dolor concreto y definido |
| **Capacidad que lo sostiene** | C-01, C-02, C-04 |
| **Velocidad de entrega** | 7–30 días |
| **Inversión** | $0–baja |
| **Repetibilidad** | Media (depende de si el problema se repite) |
| **Riesgo** | Volverse comparable con miles de "desarrolladores". Diferenciarse por **problema resuelto**, no por tecnología usada |

## Cómo se ponen a prueba (ciclo 4 semanas)

| Semana | Acción |
| :--- | :--- |
| 1 | Investigar 50 problemas reales con evidencia (`data/problems/`) |
| 2 | Filtrar: 50 → 10 resolvibles → 5 entregables en <7 días → 3 con pago razonable |
| 3 | Construir **3 OFERTAS** (no productos) y ponerlas ante personas reales (`data/experiments/`) |
| 4 | Medir: quién respondió / preguntó / pidió precio / aceptó reunión / pagó / objeciones / qué se repitió (`reports/semana4_medicion.md`) |

## Reglas del embudo

- **Antifrágil:** cada experimento debe poder fallar sin hundir.
- **Sin publicidad, logo, marca ni dominio nuevo** antes de evidencia.
- **Prohibido:** gastar los recursos disponibles en tráfico antes de saber quién compra, qué compra, por qué y cuánto paga.
- Los primeros recursos → primeros ingresos. No a anuncios.
- **No asumir que un proyecto previo es el producto.** El mercado dirá.

## Pregunta que gobierna cada oferta

> *"Con todo lo que sé hacer hoy, ¿qué puedo vender sin gastar un dólar adicional y conseguir que alguien me pague por ello?"*
